# GeoAI 自适应分析与证据路由（Skill 1.0）

本技能用于复杂 LUCC、空间统计、生态预警、政策规划和综合报告任务。它不提供新的数据或算法，而是指导 Agent 根据用户问题组合已有工具、控制分析深度、补齐必要证据并在证据充分时停止。

## 1. 何时调用本技能

满足以下任一条件时，优先调用 `knowledge_base_lookup(skill_name="adaptive_analysis")`：

- 一个问题同时包含趋势、转移、空间、风险、政策或建议中的两个及以上方面；
- 用户询问“为什么”“有什么风险”“是否符合规划”“政策是否有效”或要求综合报告；
- 已取得第一组数据，但不确定是否还需要补充其他工具证据；
- 需要判断回答应当保持简短，还是展开为分析或决策报告；
- 需要根据证据完整度形成清晰结论，既避免无证据归因，也避免在多源证据一致时仍过度降格表达。

单一数值、单一概念、单条政策和指定网页正文等简单任务不必为了形式调用本技能。

## 2. 内部任务契约

开始分析前，在内部确定以下内容。任务契约用于规划，不要求逐项原样输出给用户。

| 字段 | 需要回答的问题 |
| --- | --- |
| 用户目标 | 用户最终需要数值、变化、来源去向、空间位置、原因、风险、政策正文还是治理判断？ |
| 关键约束 | 区域、行政层级、年份或时段、地类、空间尺度、指标、资料类型和输出形式是什么？ |
| 目标结论 | 本轮最终需要支持哪一个或哪几个命题？ |
| 必要证据 | 缺少哪些 Observation 就无法回答核心问题？ |
| 补充证据 | 哪些证据只用于深化解释，且可能不改变核心答案？ |
| 允许结论 | 当前设计最多支持描述、比较、关联解释、风险研判还是政策建议？ |
| 禁止结论 | 哪些因果、预测、政策效果或空间机制无法由当前工具证明？ |
| 完成条件 | 用户所有核心子问题是否已有证据，主要结论是否可回溯？ |
| 输出形式 | 直接回答、紧凑表格、自然段分析、结构化报告还是决策建议？ |

参数优先级：

`用户本轮明确条件 > 当前会话已经确认的条件 > 当前地图上下文 > 工具默认值`

只有歧义会显著改变结果时才追问；能够从上下文安全确定时直接执行，并在最终回答中说明采用的口径。

## 3. 分析深度 D0-D4

深度表示本轮目标，不是必须逐级执行的流水线。

| 深度 | 适用问题 | 最低要求 | 停止条件 |
| --- | --- | --- | --- |
| D0 概念说明 | 指标含义、方法区别、工具能力、数据口径 | 准确定义、适用条件、项目实现边界 | 概念和限制已经解释，不强行调用数据工具 |
| D1 直接事实 | 单一数值、单期状态、单条政策、指定网页 | 一项直接 Observation；数值有单位和口径，资料有正文和来源 | 直接问题已回答，不追加无关趋势、驱动或建议 |
| D2 比较演变 | 多时段、多区域、多地类、趋势、排名和阶段 | 统一口径、关键时点、变化方向与幅度、阶段依据 | 总体变化和用户关心的比较已经得到支持 |
| D3 过程诊断 | 来源去向、空间集中、原因、风险 | 现象证据 + 对应的转移、空间或风险证据 + 机制判断 | 主要过程或风险已解释，额外工具不会实质改变结论 |
| D4 综合研判 | 政策影响、规划研判、治理、综合评价和报告 | 数据事实 + 过程或空间证据 + 权威正文 + 证据对应的判断与建议 | 事实、解释、约束和结论形成闭环，关键限制已简要说明 |

常用判定：

- “是什么、多少、有没有、正文怎么说”通常为 D0-D1；
- “变化多少、什么时候变化、哪里不同”通常为 D2；
- “从哪里来、到哪里去、集中在哪里、为什么、有什么风险”通常为 D3；
- “政策是否有效、是否符合规划、如何治理、形成报告”通常为 D4。

## 4. T1-T7 可组合任务路由

T1-T7 是任务标签，不是互斥类别，也不是七个固定阶段。一个问题确定一个主路由，并按证据缺口叠加辅助路由。

### T1 事实与状态查询

适用问题：某区域某年面积、占比、排名、单项指标或仪表盘状态。

最低证据：

- 土地面积、结构、排名：`clcd_analysis`；
- 综合仪表盘状态：`dashboard_analysis`；
- HQ/CMP/ERes/PLEC：`clcd_analysis(query_type="monitoring")`。

允许结论：当前状态、规模、占比和排名。

禁止结论：仅凭单期状态推断长期趋势、驱动原因或政策成效。

完成条件：数值、单位、年份、区域和分类口径明确；用户没有要求解释时停止。

### T2 时序演变与比较

适用问题：长期趋势、阶段变化、区域比较、地类结构变化和排名变化。

最低证据：`clcd_analysis(query_type="trend" | "comparison" | "ranking")`。

分析动作：

- 保证比较对象的年份、分类和单位一致；
- 比较起止值、净变化、相对变化或占比；
- 根据真实序列识别阶段、转折和变化节奏；
- 区分长期方向与短期波动。

可组合路由：

- 用户问来源去向时叠加 T3；
- 用户问空间落点时叠加 T4；
- 用户问原因时叠加 T5；
- 用户问风险或政策时叠加 T6/T7。

禁止结论：没有过程或外部证据时直接说明“由某政策或产业导致”。

完成条件：总体方向、幅度和用户关心的阶段已经回答。

### T3 转移路径与过程结构

适用问题：某类土地从哪里转入、转向哪里、主导转移路径、净变化和交换变化。

最低证据：`land_transfer_analysis`。

分析动作：

- 区分保持量、转出量、转入量、净变化和交换变化；
- 识别对目标变化贡献最大的路径；
- 说明转移采用 8 类口径，灌木并入林地；
- 净变化小不等于转换活动弱，可能存在较大的双向交换。

可组合路由：

- 用户问县域高发区、空间集中或重心迁移时叠加 T4；
- 用户问耕地保护、生态含义或治理时叠加 T6/T7。

禁止结论：从转移矩阵直接推出社会经济驱动力或政策效果。

完成条件：来源、去向和主导过程已经获得直接证据；用户明确问“哪里”时不能在区域总量处停止。

### T4 空间分异与迁移格局

适用问题：县域 TopN、头部集中度、空间重心、偏移距离与方向、标准差椭圆和扩张形态。

最低证据：`spatial_stats_analysis`。

分析动作：

- TopN 回答“哪里集中”；
- 集中度回答“少数地区是否占主导”；
- 重心轨迹回答“总体位置向哪里移动”；
- SDE 面积、扁率和主轴方向回答“分布范围与方向性如何变化”；
- 指标缺失或点数不足时明确无法完成对应诊断。

允许结论：有指标支持的集中、扩散、迁移方向和轴向变化。

禁止结论：

- 没有 Moran's I 或 LISA 时声称存在统计显著的空间自相关或冷热点；
- 把 TopN 称为显著热点；
- 把重心和 SDE 直接写成驱动因果。

完成条件：用户要求的位置、方向、距离或形态均有对应指标支持。

### T5 驱动解释与机制讨论

适用问题：为什么变化、异常原因、政策或发展因素可能发挥什么作用。

T5 没有能够直接输出“原因”的单一工具。先从其他路由取得事实，再组织解释。

最低证据：

- T2 的现象和阶段证据；
- 根据问题补充 T3 的过程证据或 T4 的空间证据；
- 涉及具体政策时使用 `policy_reference_lookup` 和 `web_fetch` 取得来源正文。

分析顺序：

1. 确认发生了什么；
2. 确认通过什么土地转移过程发生；
3. 确认主要发生在哪里和何时；
4. 综合时间、区域、转移过程和政策证据，判断主导机制与次要机制；
5. 仅当替代解释会实质改变结论时，简要说明关键不确定性。

禁止结论：

- 把同期政策发布等同于政策效果；
- 用实时天气解释多年 LUCC；
- 把知识图谱关系当作经验因果；
- 把当前未执行的方法写成已经完成。

完成条件：原因问题得到有数据和资料支撑的明确解释，不为显得全面罗列没有证据对应的驱动因素。

### T6 生态代理指标、预警与情景评价

适用问题：HQ、CMP、ERes、PLEC、综合风险、熵权贡献和平台政策场景。

最低证据：

- `clcd_analysis(query_type="monitoring")` 或对应的 `dashboard_analysis`；
- 工具返回的原始值、风险分、状态和权重。

分析动作：

- 区分原始值、风险映射分和综合状态；
- 区分正向指标和逆向风险指标；
- 使用实际返回的熵权结果，不自行假设权重；
- 解释用户询问的指标或对综合风险贡献较大的指标；
- 场景结果称为项目评价或约束情景，不称为真实未来预测。

可组合路由：

- 比较多年风险时叠加 T2；
- 解释风险来源时叠加 T3/T4/T5；
- 连接政策约束和治理时叠加 T7。

禁止结论：

- 将平台代理指标称为统一国家标准或过程模型真值；
- 将 PLEC 等同于主流景观冲突指数的完整实现；
- 将政策场景称为 PLUS/FLUS 空间模拟；
- 将风险分解释为现实生态损失概率。

完成条件：用户询问的风险状态、主要贡献和代理边界已解释；只问单项指标时不强制展开全部指标。

### T7 政策规划、合规解释与决策支持

适用问题：政策正文、规划要求、用途管制、政策与 LUCC 的关系、治理优先级和综合报告。

最低证据：

- `policy_reference_lookup` 定位权威条目；
- `web_fetch` 读取与问题有关的来源正文。

涉及现实土地变化、政策效果或治理优先级时，还必须取得 T1/T2 的状态或趋势证据，并按需要叠加 T3/T4/T6。

分析动作：

- 核对发布机关、文号、日期、适用层级和区域；
- 区分政策目标、管控规则、实施措施和监测到的现实结果；
- 考虑政策发布与实际实施之间的时滞；
- 对照数据判断“方向一致、存在张力或证据不足”；
- 建议与已经识别的问题、空间区域和政策约束逐项对应。

禁止结论：

- 未读取正文时声称政策明确规定某项内容；
- 用政策目标替代现实数据；
- 仅凭政策前后变化推断政策有效或无效；
- 缺少法定控制线图层时声称已经完成红线叠置或违规面积核算。

完成条件：正文依据、适用范围和来源已经明确；涉及现实判断时已有空间数据证据。

## 5. 最短充分证据链

每轮 Observation 返回后，在内部依次检查：

1. 该结果回答了哪个子问题？
2. 现在能够支持哪些结论？
3. 用户的核心问题还有哪一部分没有证据？
4. 是否存在可以直接补足缺口的注册工具？
5. 新结果是否可能改变结论、增加必要边界或满足明确要求？
6. 如果不会改变核心判断，是否应停止并生成回答？

继续调用工具的条件：

- 用户明确要求的子问题尚未回答；
- 只有趋势数据，但用户问的是来源、去向、空间位置、风险或政策依据；
- 当前解释依赖一个可由现有工具核验的关键事实；
- 多个 Observation 冲突，需要检查口径；
- 政策索引已命中，但正文尚未读取；
- 结论涉及精确数值，而当前没有对应工具结果。

停止调用工具的条件：

- 核心子问题均已有足够证据；
- 主要结论均能回指 Observation 或已读取来源；
- 额外调用只会重复同一层级的证据；
- 用户要求的是简单事实，直接结果已经充分；
- 必要能力未注册、关键参数无法确定或工具失败且没有可靠替代证据。

停止后仍需说明会影响结论的数据缺口，不能用常识或流畅表达补齐。

## 6. 证据分类与论断强度

内部区分以下证据：

- E1 平台观测：面积、结构、趋势、比较和排名；
- E2 工具计算：转移、净变化、重心、SDE、风险分和熵权；
- E3 权威正文：已经由 `web_fetch` 读取的政策、规划或公开资料；
- E4 系统知识：技能手册和知识图谱中的定义、关系与解释框架；
- E5 综合分析：Agent 基于 E1-E4 作出的比较和归纳；
- E6 待验证假设：符合专业逻辑但当前证据不能证实的候选机制。

论断强度规则：

| 证据状态 | 适当表达 |
| --- | --- |
| 工具直接返回 | “返回值为”“结果显示”“监测表明” |
| 多项证据方向一致 | “表明”“说明”“共同支持”“主要体现为” |
| 机制依据与多源事实形成解释链 | “主要与……有关”“可解释为……共同作用”“构成重要影响因素” |
| 存在会实质改变判断的替代解释 | 在结论附近集中说明一次，不逐段重复免责声明 |
| 只有时间先后 | 可说明时序耦合或方向一致，不宣称已识别单一因素净效应 |
| 有有效反事实、准实验或干预设计 | 才可讨论“影响”“导致”或政策净效应 |

政策正文结合土地变化、转移过程和空间证据，可以支持实施方向、现实响应与治理含义的综合研判，但不能单独量化政策净效应。代理指标可以支持平台口径下的相对预警和风险判断，但不等同于真实生态损失概率。

## 7. 证据冲突处理

1. 检查区域、年份、行政层级、单位和统计口径。
2. 检查是否混淆 9 类面积统计与 8 类转移统计。
3. 检查是否混淆原始值、风险分、比例和变化率。
4. 保留冲突双方，不得静默选择有利于既定结论的一项。
5. 无法消解时降低结论强度，并说明需要补充的证据。

## 8. 自适应输出契约

### 直接事实型

- 第一段直接回答；
- 补充单位、区域、年份、分类或来源；
- 不增加无关驱动、风险和建议。

### 比较与趋势型

- 结论先行；
- 用关键数值、关键时点或紧凑表格建立比较；
- 解释阶段差异；
- 说明必要边界。

### 转移与空间型

- 先给主导转移或空间结论；
- 给出决定性转移、TopN、集中度、重心或 SDE 证据；
- 进行与指标直接相关的局部解释；
- 说明分类和空间统计边界。

### 原因与风险型

- 已确认的现象；
- 过程、空间或指标证据；
- 按证据强弱排列解释；
- 替代解释和无法验证部分；
- 只有用户要求时增加响应建议。

### 政策与决策型

- 数据或问题诊断；
- 政策正文中的适用要求；
- 数据与政策目标的方向一致、现实张力或证据缺口；
- 与证据逐项对应的治理重点；
- 来源与结论边界。

### 综合报告型

报告可按任务选择研究范围、数据口径、主要结果、转移过程、空间差异、生态风险、政策解释、讨论、结论和建议，不要求全部出现。报告仍应遵守最短充分证据链，不重复同一结论。

## 9. 代表性组合示例

### 示例 A：简单查询

问题：“2023 年昆明市建设用地面积是多少？”

- 主路由：T1；深度：D1；
- 工具：`clcd_analysis`；
- 一次直接结果足够时停止；
- 不追加长期趋势、政策驱动或治理建议。

### 示例 B：趋势与阶段

问题：“分析 2000-2023 年云南省耕地变化，并指出变化最快阶段。”

- 主路由：T2；深度：D2；
- 工具：`clcd_analysis(query_type="trend")`；
- 必须使用足以识别阶段的序列，不能只比较起止两年后声称找到最快阶段；
- 用户没有问原因时不自动检索政策。

### 示例 C：转移与空间组合

问题：“2010-2020 年耕地主要转向哪里，这些转化集中在哪些县？”

- 主路由：T3；辅助路由：T4；深度：D3；
- 工具：`land_transfer_analysis` + `spatial_stats_analysis`；
- 区域矩阵回答去向，县域 TopN 和集中度回答空间核心；
- 不能只给区域总量后凭经验判断集中地区。

### 示例 D：原因解释

问题：“为什么 2000 年后云南省建设用地快速增长？”

- 主路由：T5；辅助路由：T2 + T3，必要时 T4 + T7；
- 先确认增长阶段，再确认主要转入来源和空间集中；
- 需要政策解释时读取权威正文；
- 土地变化、转移、空间和政策证据一致时，可以明确判断主导机制；没有反事实证据时，不宣称唯一原因或量化净效应。

### 示例 E：生态风险

问题：“2023 年云南省生态风险为什么较高？”

- 主路由：T6；根据指标贡献叠加 T2/T3/T5；
- 先调用 monitoring 获取实际原始值、风险分和权重；
- 只围绕主要贡献项补充土地变化证据；
- 不把风险分解释为现实损失概率。

### 示例 F：政策正文

问题：“检索并告诉我三区三线政策正文主要说了什么。”

- 主路由：T7；深度：D1；
- 路径：`policy_reference_lookup` → `web_fetch`；
- 读取正文后概括相关要求并列出来源；
- 不强行追加云南省 LUCC 数据分析。

### 示例 G：政策效果

问题：“2019 年以后耕地变化是否说明耕地保护政策有效？”

- 主路由：T7；辅助路由：T2 + T3，必要时 T4；深度：D4；
- 比较政策后变化与政策目标是否方向一致；
- 分析不同耕地流转过程；
- 明确常规前后比较不能识别政策净效应，反事实判断需要额外数据和设计。

### 示例 H：未注册模型

问题：“用 PLUS 模拟昆明市 2035 年土地利用。”

- 当前没有 PLUS/FLUS 工具；
- 可以说明所需数据、驱动因子、限制区、校准和验证设计；
- 可以用现有工具整理历史趋势作为建模准备；
- 不能编造模拟面积、空间结果或模型精度。

## 10. 最终自检

生成答案前检查：

1. 是否直接回答了用户的核心问题？
2. 区域、时间、地类、尺度和指标是否正确？
3. 是否只调用了真正需要的工具？
4. 是否还有明确子问题没有证据？
5. 每个精确数值是否来自本轮 Observation？
6. 政策结论是否来自已读取正文？
7. 是否混淆 9 类面积和 8 类转移口径？
8. 是否夸大代理指标、政策情景或知识图谱关系？
9. 机制与因果措辞是否和证据层级相称，是否既避免无证据归因又避免过度保守？
10. 是否声称执行了未注册的方法？
11. 表格、公式、标题和建议是否服务于用户问题？
12. 是否存在重复结论、固定模板或无信息量段落？
13. 会改变结论理解的关键不确定性是否已简短说明，且没有重复堆叠免责声明？

核心问题、必要证据和综合结论形成闭环时，即可结束本轮分析。
