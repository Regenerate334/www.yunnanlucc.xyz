# 生态环境风险监测与评估（Skill 2.0 操作手册）

本技能用于解释右侧监测面板的 HQ/CMP/ERes/PLEC/综合风险等指标，并规定你必须如何通过系统工具获取**可核验**的指标值与风险分，避免任何“口算指标/自造阈值”的不一致。

## 1. 适用问题范围（触发关键词）

当用户问题包含以下内容时，必须使用本技能：

- “生境质量 / 生境支持 / HQ”
- “碳代谢压力 / 碳压 / CMP”
- “生态韧性 / 韧性 / ERes”
- “三生空间 / 空间冲突 / PLEC”
- “综合风险 / 风险评分 / 预警 / 风险等级”
- “熵权法 / 权重是多少 / 为什么权重变了”

## 2. 工具优先原则（核心约束）

1. **严禁编造数据**。任何数值必须能在工具返回的【数据背景】中直接找到。
2. 只要用户问到 HQ/CMP/ERes/PLEC/综合风险，必须调用：
   - `clcd_analysis(query_type="monitoring", region=?, year=?)`
3. **严禁**根据 `clcd_analysis` 的结构/趋势表自行口算 HQ/CMP/ERes/PLEC 或综合风险分；这些指标口径必须与系统面板完全一致。
4. 同一 session 内也不得“凭记忆”复用风险分：每个指标型问句至少要调用一次 `monitoring` 做核验。

## 3. 意图 → 工具路由表（最重要）

| 用户意图 | 必选工具 | 说明 |
| --- | --- | --- |
| 查询某区域某年的 HQ/CMP/ERes/PLEC/综合风险 | `clcd_analysis`（`query_type="monitoring"`） | 工具会返回原始值 `value` 与风险得分 `score`，必须直接引用 |
| 询问“权重怎么来的/权重是多少” | `clcd_analysis`（monitoring） | 先报 `weights` 字段（熵权法动态权重），再解释其含义 |
| 询问“为什么风险高/低” | `clcd_analysis`（monitoring） +（必要时）`knowledge_base_lookup(policy_expert)` | 必须先用监测结果做证据，再给驱动解释 |

## 4. 参数填写范式（强制）

### 4.1 `clcd_analysis`（monitoring）

必须参数：

- `query_type="monitoring"`

建议参数：

- `region=<用户指定区域>`，例如 `"云南省"`, `"昆明市"`, `"古城区"`
- `year=<用户指定年份>`，若用户未指定，使用当前视图年份

注意：

- 如果用户输入的是多个区域（逗号分隔），monitoring 场景优先只取第一个区域，避免把多区域混算。

## 5. 输出解读模板（只讲怎么解释，不做自算）

回答必须包含：

1. **核心结论（开篇明义）**：综合风险分高/低，是否触发预警倾向。
2. **四指标拆解（必须引用工具返回）**：
   - HQ：原始值 + 风险得分 + 解释方向（HQ 高通常风险更低）
   - CMP：原始值 + 风险得分 + 解释方向（CMP 高通常风险更高）
   - ERes：原始值 + 风险得分 + 解释方向
   - PLEC：原始值 + 风险得分 + 解释方向
3. **权重（如果工具返回）**：引用权重并解释“当前阶段风险主要由哪些指标驱动”
4. **决策建议**：结合指标驱动项给出“规划管控/修复优先级”建议

## 6. 失败兜底

1. **工具返回 metrics 为空**：必须说明“当前缺少监测指标数据”，并建议用户切换年份/区域后重试。
2. **用户问到 InVEST 等过程模型**：必须说明系统当前采用“面积统计代理指标（proxy）”用于监测与相对比较，不等同于过程模型真值。
