AI 数据感知中枢架构图（代码可追溯版）
核心接口：`POST /api/ai/analyze-stream`；（可选）图谱接口：`knowledge_query`（MCP 工具）；图谱资产：`server/mcp/knowledge_graph.json`
交互层
src/components/ui/AIAnalysisModal.vue
问题输入与会话展示入口，渲染 SSE 分段结果，并解析 `[[MAP_COMMAND:...]]` 驱动地图联动
src/utils/aiService.js
`analyzeDataStream()` 调用 `POST /api/ai/analyze-stream`，按 `data: {content|done|error}` 解析 SSE
src/views/Workbench.vue
地图主场景与分析面板容器（viewer 由 `mapStore` 挂载），承载专题图层与监测面板联动

接口与编排层
POST /api/ai/analyze-stream
统一入口（`server/routes/ai/chat.js`）：鉴权、会话编排、流式回传
ReActAgent + CallbackManager
使用 llamaindex ReActAgent 调用工具；CallbackManager 捕获 tool-start/tool-end 事件
SSE Stream Writer
持续下发 `data: {...}` 分段消息，回传推理进度、工具结果与 `done/error` 状态
Tool Calling Trace
将 tool-start/tool-end 事件写入 SSE 文本提示（如 `[SEARCH]/[ANALYSIS]`），并可回传地图指令标签
▼ ▼ ▼ ▼
AI 规则与工具层
认知治理中枢（aiMiddleware）
`validateInput`：输入安全校验（注入/越权/离题检测）
`buildSystemPrompt`：领域约束 + 反杜撰规则 + 输出格式（统一口径）
基本原则：优先工具取证；结论必须可追溯到工具/数据库/技能库
执行调度中枢（agentTools）
专题分析：`clcd_analysis`、`dashboard_analysis`
空间与业务：`spatial_stats_analysis`、`land_transfer_analysis`
知识与交互：`knowledge_base_lookup`、`map_control`、`weather_query`（可选）
说明：工具调用事件会被回传到前端，形成可解释的执行轨迹
上下文路由（DataRouter，可选扩展）
EntityExtractor：识别地区、年份、地类与分析意图（感知输入）
ContextBuilder：拼装结构化上下文，降低工具调用歧义（提高可复现性）
备注：现阶段主链路以 ReAct 工具调用为主；DataRouter 用于快速预取/扩展接入

语义层（MCP）
server/mcp/index.js
MCP Server（STDIO），提供独立的语义增强通道（tools/list + tools/call）
knowledge_query
图谱查询工具：`metadata / search / traverse / resolve / path`（独立通道，可按需接入）
知识图谱（Graph）
以实体-关系网络组织区域、地类、指标、政策等语义对象，支持关联解释
资源与技能
`mcp://gis/skills` 与专家技能文档，支持可解释回答与规则复用
▼ ▼ ▼ ▼
数据与模型层
PostgreSQL / PostGIS
承载 `clcd_*`、`spatial_county_yunnan_*` 等核心业务数据
知识资产（UTF-8）
`server/mcp/knowledge_base.json`（知识摘要）与 `server/utils/ai/skills/*.md`（专家技能库）
知识图谱资产（UTF-8）
`server/mcp/knowledge_graph.json`（实体、关系、路径信息）
Ollama 推理引擎
承载 ReAct 对话推理与工具选择决策
主链路：用户提问 → `POST /api/ai/analyze-stream` → ReActAgent 选择并调用工具 → 数据/知识检索 → SSE 实时回传。
工具调用链（可解释）：tool-start/tool-end → 工具执行（统计/业务/知识）→ 结果归并 → 结论输出，减少“黑盒回答”。
知识图谱增强链路（可选）：通过 MCP 工具 `knowledge_query` 访问 `server/mcp/knowledge_graph.json`，返回实体关系/路径证据用于解释。
审稿关注点：链路可追踪（SSE 分段）、结论可解释（工具与数据取证）、能力可扩展（MCP 语义层）。
